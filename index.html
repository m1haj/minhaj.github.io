Resilience & post-mortems

What happens when real input is messier than the demo, written up the way a team would review it.

Driver drowsiness detection: live video that never stays clean

What the system had to do
Process live video in real time with OpenCV and Dlib and decide whether a driver was drowsy.
What made it hard
Live input varies constantly, so a pipeline that works on one clean clip is not a working system.
What I changed
I kept testing against varied real-world conditions and iterating on the system, instead of tuning for one best case.
Outcome
The system reached 90%+ accuracy under those varied conditions.

What I carried forward: on the chat server I wrote and ran test cases before deployment, so I learned how a system behaves under unexpected user behavior and edge cases before users find them.
